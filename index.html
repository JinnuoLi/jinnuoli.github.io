Security reports

I identified and reported the following vulnerabilities in candidates submitted to the NGCC competition:

  • Amoeba: incomplete FO ciphertext verification.

    The Fujisaki–Okamoto check compares only every fourth ciphertext byte, enabling chosen-ciphertext key recovery when a plaintext-checking oracle is available.

    Report (September 2026)

  • Lore: BCH decoding timing side channel.

    Secret-dependent timing in the BCH decoder enables key recovery. I reported full recovery of the Lore-L2 secret key on an STM32F4 using decapsulation timing measurements.

    Report (October 2026)
